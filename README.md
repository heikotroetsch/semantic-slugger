# semantic-slugger

Short, readable, unique IDs from any title. German + English built in. Zero dependencies.

[![npm](https://img.shields.io/npm/v/semantic-slugger)](https://www.npmjs.com/package/semantic-slugger)
[![CI](https://github.com/heikotroetsch/semantic-slugger/actions/workflows/ci.yml/badge.svg)](https://github.com/heikotroetsch/semantic-slugger/actions/workflows/ci.yml)
[![size](https://img.shields.io/bundlejs/size/semantic-slugger)](https://bundlejs.com/?q=semantic-slugger)
[![provenance](https://img.shields.io/badge/npm-provenance-blue)](https://www.npmjs.com/package/semantic-slugger#provenance)

You give it a title. It gives you an ID that people can read, say and remember: `vertrieb-nord-26`
instead of `a8f3c2e1` or `jahresbericht-vertrieb-nord-2026`. It works for any kind of text: blog
posts, tickets, recipes, meetings, papers, contracts, products, events, files. It knows nothing about
your field until you tell it (see [Teach it your field](#teach-it-your-field)).

Try it in the [playground](https://heikotroetsch.github.io/semantic-slugger/).

## Before and after

All titles are invented. The IDs are real outputs of this version (default config: 16 chars, exact
length), made in one batch, so the second "Chocolate Cake Recipe" gets a new ID.

What you see:

- Words that matter stay. Filler words (`the`, `für`, `with`), weak words (`Jahresbericht`, `Notes`) and
  noise (`500`, emoji, file endings) go.
- Long words get a short form that is still easy to guess (`choc`, `effect`, `miet`).
- Years, quarters, months, versions and parts get compact forms (`26`, `26q3`, `26mar`, `firef132`, `sprint14`).
- When the words do not fill the length, or the ID is taken, a short code ("tail") fills the rest.
  The tail has no vowels, so it never spells a word.
- Other scripts are transliterated (`Москва` -> `moskva`).

## Quick start

```ts
import { slug } from 'semantic-slugger'

slug('Jahresbericht Vertrieb Nord 2026') // 'vertrieb-nord-26'
```

Same title, same config: same ID, on every machine and in every runtime.

## Uniqueness

`slug()` does not know which IDs you already have. There are three ways to make IDs unique.

**1. You have the taken IDs in memory.** Pass them as a `Set` or a function:

```ts
import { suggest } from 'semantic-slugger'

suggest('Sommerfest 2026').id // 'sommerfest-26-jf'
suggest('Sommerfest 2026', { taken: new Set(['sommerfest-26-jf']) }).id // a new tail
```

For a list of titles, `slugMany(titles)` makes IDs that are unique within the list.

**2. Your IDs are in a database.** Use `generate()` with a store. A store answers questions like
"is this ID taken?". The library ships three: memory, SQL (any Postgres client) and Prisma.

```ts
import { generate } from 'semantic-slugger'
import { sqlStore } from 'semantic-slugger/adapters/sql'

const store = sqlStore({ query: (text, values) => pool.query(text, values) }) // pg, PGlite, postgres.js, ...
const result = await generate('Sommerfest 2026', { store, scope: 'tenant-42' })
result.id // checked against the database
```

**3. Insert and retry (recommended).** Two requests can pick the same free ID at the same time.
`createUnique()` inserts the row, and when the database says "unique violation", it picks the next
ID and tries again.

```ts
import { createUnique } from 'semantic-slugger'
import { prismaStore } from 'semantic-slugger/adapters/prisma'

const store = prismaStore({
  delegate: prisma.slugEntry,
  queryRaw: (sql, values) => prisma.$queryRawUnsafe(sql, ...values),
})
const { result } = await createUnique('Sommerfest 2026', { store, scope: 'tenant-42', retryKey: newRowId })
result.id // inserted; retryKey spreads parallel retries for the same title
```

Prisma schema for a slug table (the adapter defaults match these names):

```prisma
model SlugEntry {
  id        String    @id @default(uuid())
  scope     String
  slug      String    @db.VarChar(64)
  body      String    @db.VarChar(64)
  stems     String[]  @default([])
  titleKey  String    @map("title_key")
  algorithm Int       @db.SmallInt
  createdAt DateTime  @default(now()) @map("created_at")
  retiredAt DateTime? @map("retired_at")

  @@unique([scope, slug])
  @@index([scope, body])
  @@index([stems], type: Gin)
  @@map("slug_entry")
}
```

You can also keep the slug as columns on your own table (`fields` and `scopeWhere`). Both layouts,
the SQL table (`sqlSchema()`) and a transaction recipe are in [`examples/`](./examples).

**Transactions.** In Postgres, a failed insert aborts the transaction. Run `createUnique` outside
your transaction, or use `generate()` inside it and retry the whole transaction on a unique
violation (`isUniqueViolation(error, 'slug')`), as in
[`examples/prisma/create-document.ts`](./examples/prisma/create-document.ts).

## Config

```ts
import { createSlugger } from 'semantic-slugger'

const slugger = createSlugger({ length: 20, lengthMode: 'max', separator: '_' })
slugger.slug('Quarterly Sales Review Q3 2026') // 'sales_review_26q3'
```

`createSlugger()` checks the config and throws a `ConfigError` with the field and the reason when
something is wrong. Unknown keys are errors too.

## Teach it your field

The core is generic. It knows language (stop words, stems, compounds, number words), numbers and
time (years, months, weekdays, versions, parts), directions, and a small set of words and short forms
that are used in many fields. It ships **no** domain packs: no procurement, medical, legal or other
field data.

You add what your field needs with five options:

| Need                                                           | Option                                          |
| -------------------------------------------------------------- | ----------------------------------------------- |
| a word with a known short form (`Kubernetes` -> `k8s`)         | `lexicon` entry with `abbr` and `known`         |
| a word that should count less or more                          | `lexicon` entry with `weight`, or `weak: true`  |
| synonyms that should merge                                     | `lexicon` entries with the same `group`         |
| a product, company or project name the library does not detect | `lexicon` entry with `cls: 'name'`              |
| a place                                                        | `lexicon` entry with `cls: 'place'`             |
| a word that says which kind (`intern`, `premium`)              | `lexicon` entry with `cls: 'qualifier'`         |
| a word that names the kind of text (`Datasheet`, `Merkblatt`)  | `lexicon` entry with `weight: -60`              |
| a word that only counts in lower or upper case                 | `lexicon` entry with `lowerOnly` or `upperOnly` |
| a numbered part (`Lot 2`, `Ticket 42`)                         | `lexicon` entry with `cls: 'marker'`            |
| words to drop                                                  | `stopWords: { add: [...] }`                     |
| words that must never show (person names, code names)          | `denyTokens`                                    |
| words that must never be an ID                                 | `reserved`                                      |
| another language                                               | `languagePacks` (experimental)                  |

Three examples from different fields. They are not part of the package; copy what you need. Each
one is tested ([`test/recipes.test.ts`](./test/recipes.test.ts)).

## How it works

```
title
  -> normalize        lower case, umlauts, transliteration, remove noise (emails, URLs, file endings, ...)
  -> tokens           words, years, months, versions, parts, codes, quantities
  -> language         de or en per title (or your hook / your pack)
  -> stop words       drop filler words; mark weak words
  -> names            product and company names (iPhone, Acme Inc), acronyms
  -> compounds        split German compounds (Jahresbericht = jahr + bericht)
  -> concepts, rank   one concept per idea; score by class, rarity and position
  -> ladders          short forms per concept: vertrieb, vert, ver, vtb
  -> fit              cheapest body that fits the length
  -> resolve          check the store; re-pick or add a tail when taken
  -> id
```

- **Slot order.** The body always has the same shape: topic words first, then qualifiers (directions,
  places), then numbers and time. Inside a slot, words keep their title order. So related IDs sort
  next to each other: `vertrieb-nord-26`, `vertrieb-sued-26`.
- **Fit.** A small search tries the best concepts and their short forms and picks the cheapest body.
  Full words are cheap, cut words cost more, a tail costs most.
- **Collisions.** Same content (the same title again): same body plus a new tail
  (`choc-cake-recipe`, then `choc-cake-rec-fs`). Different content with the same body: the library
  looks at the stored rows and re-picks a body that shows the difference, when the store can tell
  (tier C below). Only when that fails does it add a tail.

## Collisions and races

- Put a UNIQUE constraint on `(scope, slug)`. The database is the only judge of "taken".
- `createUnique()` retries on a unique violation (default 5 times). Pass a `retryKey` (for example
  the new row's primary key) so parallel requests for the same title try different IDs.
- The order is fixed: for the same store state you get the same ID. The tail comes from a keyed
  hash of the title and a tail index `k`, so the n-th copy of a title gets its ID in one step.
- What the library can do depends on the methods your store has ("tier"):

| Tier   | Store has                                                | On a body collision                                                                        |
| ------ | -------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `none` | no store (`suggest()` without `taken`)                   | nothing is checked (`checked: false`)                                                      |
| `A`    | `exists` / `existsMany` only (also `suggest({ taken })`) | keep the body; try tail indexes from 0, up to `maxScan` (64)                               |
| `B`    | + `countBody` / `countBodies`                            | keep the body; start at `k = countBody(body)`; the tail grows with the count               |
| `C`    | + `findByBody`                                           | re-pick a body that shows the difference when the stored rows differ in content, else as B |

All shipped adapters are tier C. For identical titles, tiers A, B and C give the same IDs (up to 34
copies; then B and C grow the tail and A does not). For different titles that share a body, tiers can
differ. Moving to another tier can change the IDs of **new** rows; stored IDs never change, because
IDs are stored and never computed again.

## Privacy

IDs show up in URLs, logs, screenshots and analytics. Under GDPR, a person's name in an ID is
personal data. Choose what the ID may show:

| `leak`             | The ID shows                                               | Example: `Onboarding checklist for Maria Lopez at Acme` |
| ------------------ | ---------------------------------------------------------- | ------------------------------------------------------- |
| `normal` (default) | the main words, names included                             | `onb-mar-lop-acme`                                      |
| `minimal`          | topic words; drops detected names, codes, numbers, markers | `onboarding-check`                                      |
| `opaque`           | nothing: a keyed random-looking code (needs `secret`)      | `h4yf57kxc3m3prsk`                                      |

- **Names.** The library finds names only by clear signals (inner capitals like `iPhone`, a word
  before `Inc` or `GmbH`, a capital word inside an English sentence-case title, your lexicon). In
  German titles, person and city names look like any other noun, so `minimal` keeps them. For every
  name that must never show, in any language, use `denyTokens`:
  `createSlugger({ denyTokens: ['Maria', 'Lopez'] }).slug(...)` gives `onb-acme-checkli`.
- **`secret`** (16+ chars) keys the tail hash, `titleKey` and hashed stems. It is required for
  `leak: 'opaque'` and `storeStems: 'hashed'`. For multi-tenant use, give each tenant its own secret
  (for example derived from a server key and the tenant id), so tails differ between tenants.
- **What you store.** `stems` are the word stems of the title (for rarity and re-pick); with
  `storeStems: 'hashed'` they are keyed hashes instead. `titleKey` is a keyed hash of the normalized
  title.
- The [playground](https://heikotroetsch.github.io/semantic-slugger/) runs fully in your browser.
  Still, do not paste confidential data into any website.

## Write your own store

Only `exists` is required. Each optional method turns on more (see the tier table above).

```ts
import type { SlugStore } from 'semantic-slugger'

const store: SlugStore = {
  exists: async (id, { scope }) => (await db.get(`slug:${scope}:${id}`)) !== undefined,
}
```

| Method                              | Turns on                                             |
| ----------------------------------- | ---------------------------------------------------- |
| `exists(id, ctx)`                   | required: tier A                                     |
| `existsMany(ids, ctx)`              | fewer round trips                                    |
| `countBody` / `countBodies`         | tier B: the n-th copy gets its ID in one step        |
| `countStem` / `countStems`, `total` | rarity: words that are rare in your data rank higher |
| `findByBody(body, ctx, limit)`      | tier C: smart re-pick                                |
| `insert(record, ctx)`               | `createUnique()` without an `insert` callback        |

Store errors become `StoreError` with the original error in `cause`.

## Other languages

German and English are built in. For another language, add a `LanguagePack` (experimental, not yet
under the stability promise):

```ts
import { createSlugger, type LanguagePack } from 'semantic-slugger'

const nl: LanguagePack = {
  code: 'nl',
  id: 'my-nl-pack@1',
  stopWords: ['de', 'het', 'een', 'van', 'en', 'voor', 'met'],
  stem: (word) => word.replace(/(en|s)$/, ''),
}
const slugger = createSlugger({ languages: ['de', 'en', 'nl'], languagePacks: [nl] })
```

Titles in other scripts are transliterated where a table exists (Cyrillic, Greek). For others, pass
`transliterate` or a pack with its own table.

## Edge cases

| Input                                  | ID                 | Why                                                  |
| -------------------------------------- | ------------------ | ---------------------------------------------------- |
| `''`, only spaces, only emoji          | `doc-rmdngbg3z8f9` | no words: fallback word `doc` plus a tail            |
| `der die das`                          | `doc-v6vm778tj27y` | only stop words                                      |
| `2026`                                 | `doc-2026-fqnh269` | an ID never starts with a digit                      |
| `admin`                                | `admin-tz6twjvt2p` | reserved words are never a whole ID                  |
| `<b>Hello</b> &amp; World`             | `hello-world-s8js` | markup and entities are removed                      |
| `C++ Schulung`                         | `cpp-schulung-tw3` | `C++`, `C#`, `.NET` keep their meaning               |
| `SOMMERFEST  gaertnerei muenchen 2026` | `fest-muenchen-26` | same as `Sommerfest Gärtnerei München 2026`          |
| `Analyseplattform Cockpit`             | `analyseplattform` | bad-word checks look at the whole word, not at parts |
| a very long title                      | 16 chars           | input is capped at `maxInputLength` (4096)           |

## Stability and versioning

- `ALGORITHM_VERSION` is `1`. The same title, config and store state give the same ID in every
  1.x release. A change to any ID is a major release.
- Before 1.0 (now), minor releases may change IDs. The changelog says "ID output changed" when they do.
- `result.configFingerprint` changes when the config changes, so you can see which config made an ID.
- `languagePacks` is experimental and not under this promise yet.

## FAQ

**Why not slugify?** Slugify keeps every word: `jahresbericht-vertrieb-nord-2026` is long and not
unique. This library picks the words that matter, fits a fixed length, and handles uniqueness.

**Why not nanoid or sqids?** They give unique codes, but nobody can read or remember `V1StGXR8`.

**Why no `-2`, `-3` at the end?** A counter tells everyone how many items you have, and two servers
can pick the same number. The tail comes from a keyed hash, and the store decides.

**Double-click selects only part of the ID.** Browsers stop at `-`. Use `separator: '_'` or `''`,
or put a copy button next to the ID.

**`safe` or `strict` tail alphabet?** `safe` (default) is for screens: no vowels, no `0 o 1 l i`.
`strict` is for IDs that people read on the phone or type from paper: only letters and digits that
do not sound alike. Spell IDs with the NATO alphabet anyway.

**Why does a 16-char ID sometimes have a short tail?** In exact mode, a body of 14 or 15 chars
cannot take a tail (separator plus 2 chars). The library then picks a shorter body plus a tail
instead of an ugly cut. Use `lengthMode: 'max'` if you prefer shorter IDs without that tail.

## Limits

- German and English are built in. Other languages need a `languagePacks` entry or the
  `detectLanguage` hook; scripts without a table need `transliterate`.
- The built-in word list is small and generic on purpose. Add your field's words with `lexicon`.
- Language detection on very short titles is a guess. Pass `lang` per call when you know it.

## Contributing

Only synthetic titles and invented names, in code, tests, docs and issues. A new built-in word must
pass the cross-domain test: general language, or a short form used in at least three unrelated
fields. Words of one field belong in user config. Workflow: change the data, run `pnpm test:update`,
review the corpus and golden diffs, add a changeset. See [CONTRIBUTING.md](./CONTRIBUTING.md).

```sh
pnpm install
pnpm build && pnpm test && pnpm lint && pnpm typecheck
pnpm playground   # the playground on http://localhost:5173
```

Node 22.18+ and pnpm 12.8.1. The full design is in [SPEC.md](./SPEC.md).
